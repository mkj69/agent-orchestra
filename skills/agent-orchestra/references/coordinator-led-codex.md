# Coordinator-led Codex team

Use when the user explicitly requests that the main session lead the team. No separate lead agent: the coordinator owns the shared brief, frame review, integration, and final verification. Delegation still requires permission from the user and host.

1. Define one common brief with requirements, shared visual contract, target frame size/theme, renderer/test commands, interfaces, and quality criteria. Make a reservation table of worker, branch/worktree, owned files/scenes, and completion state. Split shared core from scenes and ensure no overlapping writers.
2. Send **the same common brief** plus an individual file/scene assignment to each worker, each on its own branch and worktree. Avoid copying only selected rules into individual prompts.
3. Collect frames or screenshots from every worker for all relevant scenes, times, and themes. Inspect them yourself. Return numbered notes with precise scene/time/theme or screenshot, observed issue, and requested fix to the **same worker in the same worktree** (round b); do not silently fix their files in another branch.
4. If a shared-core worker changed global visual helpers, first merge its branch into each scene branch so round-b frame reviews use the final look. Resolve conflicts with one owner and re-render affected frames; then send round-b notes.
5. Review round-b output, merge accepted work into **one** integration branch, test the combined tree, and render once from that branch. Inspect the final rendered artifact (not draft sheets) and check composition, continuity, clipping, and displayed figures independently before delivery.

If the user asks for API-key routing, use `ORCH_PREFER_API_FILE=/path/to/prefer-api` with `ORCH_API_CLAUDE` and `ORCH_API_CODEX_BIN` on **every new launch**, and create the switch file before dispatch. The router sends new lead jobs to the API regardless of `ORCH_WEEKLY_USAGE_PERCENT` while that file exists; `launch_codex.sh` selects the API-authenticated Codex wrapper or fails closed if it is unset. Weekly subscription usage may drop after a reset, so the quota percentage alone can silently route work back to subscription. This switch does not migrate running jobs; configure both wrappers' API authentication without putting credentials in prompts. Removing the switch restores quota-based lead routing and normal Codex worker launching.
